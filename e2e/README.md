# CivicPilot End-to-End Tests

Playwright browser tests cover the landing page, citizen report/evidence flow, Disruption adaptation, Ambiguity officer review, Case 1042 approval, officer queue filters, and honest metrics empty states.

## Local mock mode (default)

```sh
cd e2e
npm install
npx playwright install chromium
npm test
```

Playwright builds and starts the frontend using `NEXT_PUBLIC_USE_MOCKS=true`. Tests seed a mock officer session in browser storage, so no backend or officer password is required. The mock store uses realistic case/event/approval fixtures.

## Local or deployed live API

Set `E2E_USE_MOCKS=false`, `NEXT_PUBLIC_API_URL` to the API origin, and `E2E_OFFICER_PASSWORD` in the test process. For a deployed frontend, also set `PLAYWRIGHT_TEST_BASE_URL` to its URL. Keep secrets in the shell/CI secret store; never commit them.

```sh
E2E_USE_MOCKS=false NEXT_PUBLIC_API_URL=https://api.example.test E2E_OFFICER_PASSWORD='…' npm test
```

When `PLAYWRIGHT_TEST_BASE_URL` is set, Playwright does not start a frontend server. The live API must have the database and demo scenarios available, and its CORS configuration must allow the frontend origin. Scenario tests use IDs returned by the API rather than assuming fixed live IDs.

## Notes

- Tests run serially because the in-memory mock store is shared by the frontend process.
- Browser tests do not alter the shared API contract.
- Reports and traces are generated by Playwright when a test fails; keep them out of source control unless explicitly needed for debugging.
